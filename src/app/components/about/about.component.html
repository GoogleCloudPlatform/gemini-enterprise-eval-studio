Overview

Gemini Enterprise Eval Studio is a specialized tool for cloud engineers and AI practitioners to rigorously test, evaluate, and compare responses from Google Cloud Discovery Engine (Vertex AI Search & Conversation). It leverages Gemini as an automated rater to provide objective semantic similarity scores and user defined rubrics along with the latency metrics.

Getting Started

1. Prerequisites

  • Enable Agent Platform API in your GCP project: In the Google Cloud Console, navigate to "APIs & Services" > "Library", search for "Agent Platform API", and enable it.
  • Enable Discovery Engine API in your GCP project: In the Google Cloud Console, navigate to "APIs & Services" > "Library", search for "Discovery Engine API", and enable it.
  • Authentication (Auth Mode): Sign in using your Google Workspace account or a third-party enterprise identity provider (via Workforce Identity Federation OIDC/SAML) to authorize the tool to access Vertex AI and Discovery Engine.
  • Google Cloud Access Token (No-Auth Mode): You can get this by running gcloud auth print-access-token in your terminal. You can open Cloud Shell (terminal icon on the top right of the Google Cloud Console home page) to run this command.
    Note: that these tokens are ephemeral and expire, so you may need to refresh them periodically.
  • Discovery Engine Setup: Ensure you have engines configured in your Vertex AI Search project.

2. CSV Formats

For Run Evaluation

Your CSV must contain at least these two columns:

  • query: The search or conversation prompt.
  • golden: The expected ideal response (baseline).
  • conversation_id (Optional): Groups multiple rows into a multi-turn conversation sharing the same Assistant session context.
  • turn (Required for multi-turn): Consecutive numeric turn order within a conversation starting at 0 or 1 (e.g., 1, 2, 3). If a turn ID is missing or non-consecutive, remaining rows in that conversation are marked as SKIPPED.

For Run Queries

Your CSV only needs:

  • query: The search or conversation prompt.

3. Metric Definitions

  • TTFT (s) (Time to First Token): Latency in seconds until the first chunk of data (text or thought) is received from the model.
  • TTFA (s) (Time To First Answer Token): Latency in seconds until the first actual text response (excluding internal chain-of-thought) is received.
  • TTLT (s) (Time To Last Token): Total time in seconds taken for the entire response to stream.
  • Score: A score (0.0 to 1.0) calculated by Gemini based on your defined rubrics or metrics, comparing the fetched response to your golden response.

4. Interpretation of Results

  • Delta (Δ): Calculated as Recent Score - Baseline Score.
  • Improvement (Green): Delta > +0.10.
  • Regression (Red): Delta < -0.10.
  • Stable (Gray): Changes within +/- 0.10 range.

Data Privacy & Governance

Sensitive tokens and keys (such as the Google Cloud Access Token) are kept only in memory during your session and are not stored in your browser's local storage. They are never sent to any server other than directly to Google's official APIs during execution.

Gemini Enterprise Eval Studio is designed with a strict client-side, stateless architecture:

  • GCP Tenant Isolation: The tool operates entirely within your Google Cloud Platform (GCP) tenant. All computations, evaluation runs, and data storage occur within your controlled environment.
  • No Google Data Collection: Google does not collect, store, or have access to your customer data, queries, evaluation inputs, or evaluation results processed by this tool.
  • Governing Agreements: Any data handling and API calls made by the tool are governed solely by your existing agreements with Google Cloud for the specific APIs used (e.g., Vertex AI APIs).
  • Exported Data Responsibility: Query and evaluation results exported to CSV may contain Customer Core Content (such as queries, golden responses, model responses, and scores). Once downloaded, these files are stored on your local filesystem, outside of your Google Cloud environment. You are solely responsible for securing and protecting exported files in accordance with your organization's data handling policies, including restricting access, storing them securely, and deleting them when no longer needed.
